# 性能测试（JMeter 集成首版）

入口：测试工具 → 性能测试，地址 `/jmeter`。原有本机 GUI 启动接口已替换为工作台任务接口；无需启动桌面 JMeter。

## 快速体验

1. 在工作台顶部选择一个项目。
2. 使用「HTTP 快速场景」，填写被测 GET 地址。默认 `http://127.0.0.1:8000/health` 只用于本机功能体验；测量工作台自身会影响结果，不作为正式性能基准。
3. 设置并发数、升压时间、持续时间和验收阈值，点击「开始测试」。
4. 在右侧查看采样数、累计吞吐量、平均响应、精确样本 P95、错误率及累计 P95 趋势。页面约每 2.5 秒刷新，后台约每秒采集。
5. 完成后查看内嵌 HTML 报告，下载 JTL 或日志；下方可切换历史记录。刷新、离开再回来仍能查看任务。

## 导入已有脚本

选择「已有 JMX 脚本」，一次上传一个 `.jmx` 和最多 10 个配套 `.csv`，每个文件不超过 10 MiB。CSV 引用使用相同目录的文件名，不支持绝对路径或子目录。每次导入创建新的脚本记录，每次运行复制独立快照，不覆盖历史。

脚本须读取下列属性，页面参数才能生效（可下载模板参考）：

| 设置 | JMX 属性值 |
| --- | --- |
| 线程数 | `${__P(threads,5)}` |
| 升压时间（秒） | `${__P(ramp_seconds,5)}` |
| 持续时间（秒） | `${__P(duration_seconds,30)}` |

普通线程组须开启调度器。导入检测仅检查参数引用存在，无法保证任意插件/自定义脚本遵守参数和并发上限；需审查实际线程组配置。缺少引用的脚本可保存，但不能直接运行。首版无完整 JMX 在线编辑器。

环境和版本可从工作台现有数据中选择，也可填写，运行时保存名称快照。它们是归档标签，不会自动改写脚本目标地址。

## 执行与数据

- 复用本机 JMeter 5.6.3 与 Java，`JMETER_HOME` 优先，否则按仓库位置定位 `tools/apache-jmeter-5.6.3`；Java 优先使用 `JAVA_HOME/bin/java`，其次 PATH。
- 使用 Java 参数数组启动 CLI，无 shell 拼接，无桌面窗口。首版面向本机单用户、单后端进程部署；同时仅一个任务，不支持多 worker 或分布式执行。
- 页面配置范围：1–200 用户，持续 1–3600 秒。引擎超时上限为持续时间 + 升压时间 + 60 秒；报告生成最多 180 秒。固定 Java 最大堆 512 MiB，适合体验与小规模任务。
- 停止为强制停止所属进程树，保留已有结果；不保证已发请求或事务完成，停止任务不自动生成报告。Windows Job Object 在后端退出时回收其 JMeter 子进程，服务重启后将遗留运行记录标为中断。
- “已完成”是执行状态；“指标达标”需同时满足错误率和 P95 阈值。无采样、进程非零退出视为执行失败。报告生成失败会明确提示，仍保留有效采样指标。
- 首版采用与现有本机任务工具相近的文件持久化方式，不新增 MySQL 表。`backend/runtime/jmeter/scripts/` 保存脚本，`runs/` 保存冻结输入、配置、JSON 元数据、JTL、日志和报告。整机迁移须保留该目录；已加入 Git 忽略，含接口地址或业务数据的运行文件不会随源码提交。
- 使用每次运行独立的英文引擎配置，规避当前汉化包报告百分位标题的格式错误；工作台仍为中文，不修改本地 JMeter 安装配置。

## 信任与访问边界

所有接口及报告资源要求工作台管理员会话；导入与运行检查项目，文件读取限制到运行结果/报告目录，拒绝目录穿越和 XML DTD/实体声明。运行日志读取仅返回末尾 64 KB。

JMX 可执行本机代码，因此仅导入可信脚本，当前单用户本机执行器不是不可信代码沙箱。报告是可信脚本生成的本机 HTML，iframe 允许同源脚本以支持鉴权资源及 JMeter 图表 cookie；CSP 限制外部资源、网络连接、表单、插件及顶层导航。多人或不可信脚本场景应先独立隔离执行器与报告域。

## 验证

`backend/tests/test_jmeter.py` 覆盖输入校验、XML/路径边界、项目过滤、鉴权、报告资源访问、增量统计、重启状态，以及真实 JMeter 单用户 2 秒采样、报告生成和停止。真实测试使用临时本机 HTTP 服务，不访问外网；无 JMeter/Java 时跳过该项。
